# C 设备会话适配层

`session.h` 定义独立的设备会话接口。模块不打开串口、不加载模型、不创建控制循环，也不调用旧版 `edge/rig.c`。发送函数由调用方提供，时间由同一个单调时钟传入。因此宿主单元测试不需要设备或 NPU。

## 数据与调用关系

1. 调用方读取设备配置，并以 `device_limits` 传入目标速度、加速度、软边距和会话超时。训练设备参数的权威来源是 `source/cartpole/cartpole/data/device-profile.json`；适配层不保存第二套默认参数。
2. 创建会话不会发送任何命令。调用 `device_session_refresh` 只发送 `QUERY`、`CALIB?` 和 `CONFIG?`。发送回调必须保证整条命令按顺序提交，部分写入也返回失败。
3. 调用方切分完整串口行，逐行调用 `device_session_feed`；每次控制迭代先调用 `device_session_tick`。单个会话必须由同一线程拥有。读取超过接收预算的积压数据不是新鲜采样，调用方必须在串口适配边界检测积压并停止会话，不能给历史字节重新标记时间来证明新鲜度。
4. 人工完成左参考和使能后，调用方显式调用 `device_session_start`。此函数仅切换本地会话状态，不发 `ENABLE`、`CONFIG`、`RESET` 或定位命令。
5. `device_session_action` 接受有限的 `[-1, 1]` 动作并按配置速度映射为 `VEL`。位于标定半行程减软边距之外时，只封锁朝外的动作。此边界不是提前制动或物理停车保证。

`start` 要求：模式为 `READY NONE`；`CAL_STATE=2`、`CAL_SAVED=1`、`CAL_STORAGE=0`；有效行程在100～1000mm；`VEL_MAX`、`ACC_MAX`、`WDT_MS`、`WDT_DEC` 和 `X_MARGIN_UM` 的回读等于传入配置；两路有效性均为1；状态、心跳、模式与所有参数未过期。建议调用方使用100ms状态年龄、300ms有效性心跳年龄、1s元数据年龄，启动前刷新查询。活动会话继续要求所有门限成立；调用方每0.5s显式调用refresh查询，不能一直依赖启动时的READY和标定缓存。MODE或关键配置值变化也会锁存失败。start同时要求位置严格在软边界内。

活动会话遇到测量无效、模式变化、过期数据、畸形关键行、非有限动作、时间倒退或发送失败时，清除缓存并锁存失败。活动会话随即进入有界停止阶段，继续零速和禁用流程；恢复数据只用于完成停车，不会恢复策略控制。发送失败或时钟失效时最多尝试一次额外 `VEL 0` 后结束，不会递归重发。现场处理完毕后，调用方必须销毁旧会话，重新创建并重新查询，不能自动重启控制。

当串口适配层检测到积压或策略推理失败时，调用公开的 `device_session_abort`。观察阶段直接结束，不发送运动命令；活动阶段锁存 `DEVICE_APPLICATION_ERROR` 并进入有界停车。停车阶段再次调用不会覆盖首个错误或延长截止时间。调用方不需要伪造坏行，也不应访问内部实现。

## 正常停止

调用 `device_session_stop` 后，模块发送 `VEL 0` 并丢弃旧状态。只有此后收到有效、未过期的零速 `STATE`，才发送 `DISABLE`；只有收到相应阶段的 `MODE DISABLED NONE` 才将 `disabled_confirmed` 置为true并进入 `DEVICE_FINISHED`。零速状态只是报告值，固件仍会以引擎精确零速判断是否允许禁用。

调用方继续喂行和调用 `tick`：在停止期限内每隔至少30ms可续发一次零速，`ERR BUSY` 允许后续重试禁用。停止时遇到FAULT不会自动RESET；停止期限耗尽则结束并报告未确认，不能将 `MODE FAULT` 或报告速度0当作禁用成功。故障后的独立断电和机械处置由现场完成。

## 验证与待完成集成

在仓库根目录运行公开接口单元测试：

```sh
cc -std=c11 -Wall -Wextra -Werror -pedantic \
  deploy/v2/device/edge/session.c deploy/v2/device/edge/session_test.c \
  -lm -o /tmp/device-session-test
/tmp/device-session-test
```

测试使用受发送接口约束的替身与显式时间，不包含实现源文件、不访问私有状态。它验证的是会话状态转换，不是串口/NPU/固件的真实组合。

目标机串口适配、缓存积压检测、模型元数据校验、500Hz调度及NPU控制循环尚未接入此模块。500Hz是训练与部署目标，不是宿主调度保证。`device_session_feed` 返回false表示关键行处理出错或存在已锁存的故障；停止阶段仍需继续传入后续行与时间，直到 `DEVICE_FINISHED`。快照中的error会保留最初故障，即使最终确认禁用也不将试验改判为成功。

实际端到端时延、连续运行、停止距离、目标交叉编译和真机闭环仍需独立验证。线协议没有采样时间戳与序号，接收时间不能证明设备样本的新鲜度。
