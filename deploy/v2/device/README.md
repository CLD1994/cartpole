# 当前设备的主机会话接口

本目录提供 Python 和 C 的设备会话状态机，以及 Python 只读检查器。它们处理协议、有效性、启动条件和禁用回执，不包含模型推理器，不自动使能、不回零、不回中，也不会替操作者确认左端位置。旧 `../pc_runner.py` 与 `../edge/main.c` 是独立入口，不能直接运行新的 500 Hz 模型。

## 读取设备状态

在仓库根目录运行：

```powershell
python deploy/v2/device/check.py --port COM11 --seconds 2
```

需要 `pyserial`。程序仅发送 `QUERY`、`CALIB?`、`CONFIG?`，不发送 `CONFIG`、`ENABLE`、`CONFIRM LEFT` 或 `VEL`。`preflight_reason=null` 只说明本次接收值满足会话入口条件，不证明设备安全、模型匹配或采样到动作的真实延迟。程序不以退出码代替此字段。串口必须独占；不要同时运行旧控制器或固件维护工具。

设备目标参数来自包内 [设备档案](../../../source/cartpole/cartpole/data/device-profile.json)，Python 不导入 Isaac Lab。控制频率目标500 Hz、速度映射上限1250 mm/s、加速度配置10000 mm/s²。**本目录没有调度器，不能保证500 Hz，也未实现450–500 Hz模型的可变步长。** C 接口接受集成方传入这些值，不能从旧 `edge/config.h` 取默认值。

## 会话合同

Python 使用 `Session(transport, clock, limits)`。串口协作者只实现完整写入或错误；时钟使用单调秒数。C 使用显式时间和发送回调，详见 `edge/session.h`。调用方必须保证写入有界、独占串口，并周期调用超时检查及 `refresh` 查询；状态机不能中断卡死的外部 I/O。

| 阶段 | 条件与行为 |
| --- | --- |
| 观察 | 清空旧预检缓存，只发查询。允许编码器预热后恢复，不发送运动。 |
| 启动 | 调用方显式请求。最近1秒内收到READY/NONE、有效标定、配置读回；最近100ms内收到STATE，最近300ms内收到VEL_VALID 1 1。启动本身不ENABLE也不发VEL。 |
| 活动 | 每次动作前检查数据及1秒内的模式/参数读回；调用方每0.5秒显式刷新查询，过期锁存停止；有限动作[-1,1]乘目标速度得到mm/s。越过由标定长度与软余量派生的边界时封锁向外目标。 |
| 停止 | 停发非零目标，发送VEL0；后续新鲜零速STATE只允许请求DISABLE。只有请求之后的MODE DISABLED NONE才确认禁用。ERR BUSY可重试，但1秒截止不延长。 |
| 结束 | 不允许自动重启。数据恢复不能解除本次失败锁存；必须另建会话并重新查询。 |

创建会话时，Python 的固件配置字段只接受整数，不接受布尔值、字符串或小数；C 使用整数类型。两端均按当前固件协议校验：速度1–2000mm/s、加速度及看门狗减速度100–30000mm/s²、看门狗10–1000ms、软余量1000–50000µm。频率和超时时间必须是有限正数。协议允许范围不是机械能力保证，预检仍要求设备读回匹配，并检查实际行程可容纳余量。

完整启动读回包括 `CAL_STATE=2`、`CAL_SAVED=1`、`CAL_STORAGE=0`、100–1000mm范围内的 `CAL_LENGTH_UM`，以及与注入参数匹配的 `VEL_MAX`、`ACC_MAX`、`WDT_MS`、`WDT_DEC`、`X_MARGIN_UM`。默认看门狗策略是100ms与5000mm/s²。检查器不替用户修改不匹配的配置。已知查询字段的回执缺值或格式错误时，对应旧读回立即失效，必须重新收到合法值。

`CAL_STATE=3` 表示保存记录存在但本次左参考未确认。操作者应在固件工具中完成实物定位与 `confirm-left`，核对后另行 `enable`。会话接口不能根据当前位置数字证明小车在真实左端。

有效性变为0、STATE或有效性超时、活动期间的固件故障/模式变化、关键回执变化、坏格式状态行和无效动作都会阻止继续发非零目标，并清除缓存。停止过程中继续接收恢复数据仅用于有界停车/禁用确认，不恢复运动。发送失败终止会话；失去通信时无法凭软件确认停车。停车阶段收到测量无效、固件故障或非 `ERR BUSY` 错误时，仍保留首次失败；即使之后确认禁用，也只表示禁用完成，不表示控制会话成功。上层必须检查禁用确认与失败原因，不得用“函数返回了”代替结果。

`Observation.si()`只做单位转换，保留固件坐标符号。模型适配方必须核实导出模型的观测顺序、符号、归一化、动作含义和设备档案，不能未经核实继承旧入口的摆角翻转。训练模型没有在本工作区运行过，不能把会话单测通过当成策略闭环完成。

## 验证与边界

```bash
python -m unittest discover -s deploy/v2/device -p 'test_*.py'
make -C deploy/v2/device/edge test
```

这些单元测试注入发送与时间，通过公开接口验证状态转换，不连接设备。维护者还需在合并后的固件上验证协议组合、目标机串口读写时限、模型推理与控制循环，以及停止/禁用结果。没有在本次工作中运行硬件集成测试。

状态行不含设备采样时间戳或序号，主机接收时刻不等于采样时刻；串口积压不能靠上述接收超时证明已消除。停机读数也不证明机械静止、无打滑或电机实际电流。软边界是最后一层命令限制，不提前规划制动距离。外部推理或接收适配器发现异常时调用公开的 `abort` 接口，锁存停止；不要伪造协议行触发内部处理。本接口不授予高速度试验或无人在场运行的条件。

只读检查器退出码为0表示本次检查结束时预检满足、没有接收错误且没有会话失败；否则退出码为1。JSON中的 `preflight_reason`、`receive_error` 与 `session_failure` 分别说明三个层次的结果。退出码0不表示已启动策略、设备已使能或物理运动已经验证。

## 有界接收适配

Python 的 `Receiver(source, session, clock, limits)` 和 C 的 `edge/receiver.h` 负责把字节流拆成完整协议行。Python 只读检查器已经使用此接口。C 集成方提供查询待读字节数、读取字节和时钟回调；本目录不提供 C 操作系统串口驱动。接收器与会话必须共享同一单调时间轴，串口必须独占，读回调必须非阻塞，写回调也必须有界。接收器只能在回调返回后发现超时，不能中断卡死的驱动。

Python 和 C 均要求 `1 ≤ max_line ≤ max_pending ≤ 1048576`，时间阈值为有限正数。Python 的字节计数只接受整数，所有参数拒绝布尔值，时间阈值也不接受字符串。非法配置在创建接收器时拒绝，不执行 I/O。

默认 Python 阈值如下，C 调用方通过 `device_receive_limits` 显式传入同类阈值：

| 项目 | 阈值 | 超过时的行为 |
| --- | --- | --- |
| 待读队列 | 1024字节 | 不把积压数据交给会话，锁存接收故障。 |
| 单行 | 256字节，不含换行符，包含可选的回车符 | 丢弃本批，锁存接收故障。 |
| 两次轮询起点间隔 | 20ms | 在读取前锁存故障。 |
| 一次队列查询和读取 | 10ms | 返回后丢弃本批，锁存故障。 |
| 未完成行的等待时间 | 20ms | 读前和读后均检查，跨过期限也丢弃本批。 |

每次 `poll` 先检查会话期限，至多进行一次读取，读后再次检查会话期限和队列大小。只有整批字节均为允许的ASCII字符、所有行长度有效，才向会话交付完整行；剩余分片等待下一次轮询。错误不会通过后续正常数据清除。接收器调用公开 `abort` 接口，活动会话进入停止流程，观察会话直接结束。

`poll` 的真假值仅表示这批接收是否符合接收契约，不代表会话健康或停车完成。停止阶段应继续轮询到会话结束，并分别检查会话失败原因与禁用确认。一次失败后，接收器先丢弃到下一换行边界，再恢复完整行交付，避免截断数据冒充回执。持续积压或I/O错误可能一直阻止回执交付，最终只能得到未确认停机；接收器不会无限排空队列或自动恢复控制。Python 会话抛出的致命异常（例如单调时钟无效）向调用方传播，不能仅凭 `Receiver.error` 判断这类终止。

这些阈值用于发现主机停顿、积压、损坏和迟到分片，不证明设备采样新鲜。低于阈值的旧缓存仍可能到达；协议缺少采样时间戳与序号，不能据此承诺端到端延迟。非阻塞串口、轮询阈值在Windows及目标板上的适用性、C驱动绑定、会话与接收器的真实组合，以及持续控制负载下的停止确认，仍需现场验证。接收器单元测试使用公开接口约束的会话和I/O替身，不包含硬件或新增集成测试。

### 动作整数化

会话接收有限的归一化动作 `[-1, 1]`，乘以注入的速度上限后转换成整数 mm/s。Python 与 C 均取最近整数，恰好半单位时远离零，例如 `0.5 → 1`、`-0.5 → -1`。范围外或非有限动作仍触发失效停车，不在会话内部静默钳位；模型输出钳位属于上层策略适配的职责。

## 只读策略影子运行

`shadow.py` 将新设备接收器与 ONNX 推理连接起来，仅记录预测，不是电机控制器。运行前保持设备禁用，关闭其他串口程序，不需要使能、回中或改变配置。打开串口前设置 DTR/RTS 为低；USB/驱动仍可能在打开端口时导致设备复位，因此不能将打开串口视为机械安全措施。

```powershell
python deploy/v2/device/shadow.py --port COM11 --onnx <model_1050对应的policy.onnx路径> --seconds 10 --output .\logs\shadow\model1050-readonly.json
```

端口应使用实际枚举结果，输出文件必须尚不存在。依赖 `pyserial`、`onnxruntime` 和 `numpy`，无需启动 Isaac Sim。推理使用 CPU、单线程 ONNX Runtime；这不改变训练或仿真后端选择。模型若含外部权重文件，必须保留完整导出目录。本程序校验四维 float32 输入、单动作输出和有限数值，但不能从网络形状证明观测含义或归一化正确，必须由导出流程确认。

| 项目 | 行为 |
| --- | --- |
| 串口写入 | 只允许 `QUERY`、`CALIB?`、`CONFIG?` 三条查询；写入适配器拒绝其他字节，不发送 `VEL`、`ENABLE`、`DISABLE` 或配置。 |
| 角度方向 | 默认对同一观测分别使用正角量和反角量推理，报告 `angle_sign`。不自动选择正确方向，不依据动作值大小判断方向。 |
| 状态有效性 | 使用接收器与会话的速度有效性和接收新鲜度门控。无有效新观测时不推理；报告保留固件模式、标定和配置读回。没有检查通过的标定，预测不能用于物理判断。 |
| 推理异常 | 输出非有限值、输入输出接口不匹配、接收积压或通信错误时结束记录，返回非零退出码。 |
| 调度 | 目标每2ms检查一次；错过拍点后不补发，不对同一接收时间戳重复推理。测量循环间隔、调度迟到和每次推理耗时。 |
| 退出 | 报告写入完整数据。Ctrl+C记录 `interrupted`；只读模式不需要也不会发停车命令。它不是正在运行设备的安全监护器。 |

`complete` 只说明在指定时间内获得了有效观测并完成影子记录，不代表预检通过、标定匹配、500Hz闭环达成或模型可部署。默认双方向会执行两次推理，其整体吞吐不能当作单策略闭环速度；可在方向独立确认后使用 `--angle-sign positive` 或 `negative` 做单方向只读测量。时间来自主机接收及调用时钟，固件没有采样时间戳，不能推导端到端采样延迟。报告按结束时一次性写入，避免每步磁盘输出扰动节拍；主机崩溃或被强杀可能留下空文件。

影子运行不会消除模型训练频率、实机控制节拍、状态符号与执行器映射的核验要求。真实闭环入口、有限时长控制、首次运动条件和停机验收仍需单独实现与现场确认。

### Windows 计时修正

影子入口统一使用 `time.perf_counter` 驱动调度、会话、接收器时间戳与推理计时。CPython 3.12 Windows 的 `monotonic` 使用 `GetTickCount64`，粗粒度可能使2ms调度实际等待约16ms，短推理被记作0秒；换成纳秒单位不能修复底层分辨率。报告记录两种时钟的实现及分辨率。

保持 Python 3.12 自带的高精度 `time.sleep`（每次最多200µs），新增 `sleep_wall_s` 记录真实等待。不调用 `timeBeginPeriod`，不修改系统计时器、进程优先级或采用忙等。Windows调度仍可延迟，只有新的实测循环、接收与推理数据能说明吞吐，不保证500Hz。此修改不影响固件、不改变三种查询白名单，也不授予运动权限。

## 限时真实策略入口（尚未经硬件闭环验证）

`run_policy.py` 是独立于只读 `shadow.py` 的运动入口。**不要仅为了让预检通过而使能或修改固件参数。** 当前型号/导出、坐标和现场停止条件未确认前，继续只读；`model-contract.example.json` 故意不能运行。合同布尔值只是人工审阅声明，不是物理安全证明。历史 `sim2real-spec.md` 支持角度和角速度取反，其余保持，但必须匹配当前 USD/导出与当前台位，不能据此重写台位零点。

此入口不发送 ENABLE、CONFIG 或 CONFIRM LEFT，不回中、不起摆。操作者须独立完成本次定位、台位配置核对和使能，命令必须显式含 `--start-confirmed`。程序最多等待2秒预检，不会无限等到某次使能后突然启动。输出文件独占创建，模型初始化先于串口打开。

启动要求当前 Session 预检满足（包括 READY/NONE、CAL_STATE2、保存标定、1250mm/s及10000mm/s²等完整读回），标定长度与档案853325µm一致，并处于中心±0.2m、直立±10°、车速≤0.05m/s、角速度≤0.5rad/s。档案参数来自历史记录，**不是已经证明对本次设备状态安全**。持续控制仅限制±0.2m和±20°，这些边界不保证足够制动距离。动作按训练比例1.25m/s映射；没有降低速度上限来假装同一策略，也不允许强制绕过预检。

首次原型单次默认及最大0.5秒；Ctrl+C、异常、超时或越界进入有界VEL0/测量零速/DISABLE流程。`disabled_confirmed`只说明收到固件禁用回执，不能证明机械静止。串口异常、OS停顿、进程强杀、驱动阻塞、第二次Ctrl+C可能使软件无法确认停车；现场必须能独立停机，不能将此Python进程当作安全控制器。

目标500Hz，但只读实测约458Hz，训练未实现可变控制周期。入口保留实际循环/推理计时，4ms观测年龄和额外2ms调度迟到限制用于尽早中止，不构成硬实时保证；主机接收时间不等于设备采样时间。短暂通过也不是频率适配验证。此入口无自动重试或故障后恢复运动。

闭环合同还绑定本次实际读回 `POLE_ZERO_URAD`、`POLE_INV`、`X_INV`，启动前CONFIG?读回并纳入新鲜性和变更检查。不会写回或使用示例默认值覆盖台位。活动阶段待读队列超过128字节即中止；首次0.5秒原型不在活动期发查询，避免组合配置回包超过4ms动作预算。元数据仍遵守Session的1秒有效期；发送前要求已接收内容完整到换行、驱动队列为空。仍存在检查后到写入前竞态以及USB/驱动隐含缓冲；不能据此证明设备采样时间或绝无迟到故障。

每个非零策略发送前还执行条件性制动包络：`v=max(|实测速|, |目标速|)`，要求剩余软限位距离大于 `0.15*v + v²/(2*a) + 0.05` 米，`a`取配置加速度与看门狗减速度的较小者。150ms反应预算与50mm余量是保守试验假设，不是实测保证；若实际减速度不足、失步或故障仍可失效。1250mm/s、5m/s²时要求约394mm，所以仅在中心附近约±23mm内才允许这一满速动作，其余拒绝并停车，不悄悄改变模型动作尺度。程序区域限制不是机械安全认证。

`motion_command_attempted` 在写入前标记，短写或超时也意味着设备可能已收到动作；`motion_command_sent`仅表示写调用完整返回，不是机械运动测量。未收到禁用确认时会明确报告 `stop_unconfirmed`，有界尝试零速后不能声称已经停车，必须依靠现场独立停机；看门狗仅是条件性兜底。

首条动作必须在启动后4ms内、后续动作必须在上次完整写入后4ms内尝试，重复观测不能无限等待而延续上一速度。发送前有未完成帧或剩余队列立即中止，不跳过后继续维持非零目标。所有元数据查询必须在启动前完成，首轮只覆盖0.5秒，不是持续闭环实现。半行在持续流中可能正常出现，目前采用保守中止，尚未通过实机验证适用性。空动作记录不能报告完成。

参考固件仓库 `tools/probe_link.py` 与 `tools/cartpole_host.py`（已核对main `a5bc363`）：启动先丢到首个换行再查询，保留跨读取的半行、门控VEL_VALID、在运动期间用内存日志、有界读写和故障停止。这些现成工具有0.1秒新鲜度及2ms/5ms等待，不能原样作为500Hz策略循环；当前保留本仓库既有Session/Receiver而不复制另一套协议。固件运动探针的200ms低速/位置稳定判定与这里Session的禁用回执不同，本程序未声称复现探针物理停稳验证，也没有替代它们。

### ONNX外部权重完整性

闭环入口额外依赖 `onnx`，在打开串口之前解析主文件（不加载外部数据），遍历所有嵌套张量引用并验证合同 `external_data_sha256`。清单必须与图中实际引用文件集合完全相同；单文件模型必须显式写 `{}`，不是假定所有模型只有一个 `.data`。文件可在导出目录的子目录中，拒绝绝对路径、越界、重复location字段和缺失文件。每个文件核验完整SHA256，包括使用offset/length的共享外部文件。模型加载预热前后各核验一次，任何缺漏或哈希不符都在打开设备前拒绝。运行期间不得改动导出文件；这不是对并发恶意修改的文件锁保护。

本次操作者提供的model1050文件清单（未由本机重新读取实物文件）：

```json
{
  "onnx_main_file_sha256": "0808d20dbe9b8abf66bbeb45ec65cec41df165d2f9b06814d0b346879e834b8e",
  "external_data_sha256": {
    "policy.onnx.data": "1f899c46ae54365f59b19d0c1af8918a52590097f14924be53ec996e7b39faf4"
  }
}
```

清单只绑定文件身份，不替代坐标、归一化与现场条件确认。若图中引用还有其他文件，程序会拒绝，必须核实并补全真实清单，不能通过忽略引用规避检查。

### 启动拒绝后的安全收尾与编码

预检后即使没有发送策略动作，只要已读到 `READY NONE`，失败或中断也显式请求现有零速→新状态停稳检查→DISABLE流程；不会自动ENABLE，不重置已经开始的停车截止。报告分开记录 `motion_command_attempted`、`safe_stop_requested`、`disabled_confirmed`、`stop_unconfirmed` 和最后观察到的固件模式（不是未确认停机时的实时状态保证），拒绝启动不再意味着直接留下已使能设备。通信失败、驱动阻塞或未知模式仍不能保证停机，现场独立停机措施必须保留；禁用确认不是机械停稳证明。

`initial_state_check` 和触发时的 `failed_state_check` 保存当时观测、主机接收/检查时间及实际使用阈值，避免只看到笼统越界信息。输出仍拒绝覆盖已有报告。

合同按UTF-8读取（接受BOM），JSON报告写UTF-8。PowerShell生成含中文合同请用下面方式，不要 `-Encoding ascii`（已经写成问号的文本无法恢复）：

```powershell
[System.IO.File]::WriteAllText($contract, ($contractObject | ConvertTo-Json -Depth 6), [System.Text.UTF8Encoding]::new($false))
```

此收尾只覆盖进程已经连接设备并观察到READY的情形。模型加载、合同、依赖检查在打开串口之前失败时，脚本不知道设备状态，也不能自动禁用此前由操作者使能的设备。必须保留外层退出后的状态检查；正常返回、异常或Ctrl+C都不能仅看Python退出码判断禁用。外层命令自身若无法通信，使用现场独立停机措施，不宣称软件已停车。

### 禁用设备上的调度诊断（不再次驱动）

`diagnose_timing.py` 复现主机“到拍→是否有新观测→推理→再次收包→虚拟动作”的时序，串口仍由三查询白名单保护，**没有VEL/ENABLE/DISABLE/CONFIG写入**。必须先独立禁用；脚本读到非DISABLED模式立即退出，本身不是停机工具。可以让杆自然下垂，不需要手扶直立。

```powershell
python .\deploy\v2\device\diagnose_timing.py --port COM11 --onnx "$onnx" --scheduler legacy --output ".\logs\deployment\timing-legacy-$(Get-Date -Format yyyyMMdd-HHmmss).json"
python .\deploy\v2\device\diagnose_timing.py --port COM11 --onnx "$onnx" --scheduler wait-fresh --output ".\logs\deployment\timing-waitfresh-$(Get-Date -Format yyyyMMdd-HHmmss).json"
```

两种模式保留4ms虚拟动作间隔截止：legacy在缺新状态时推进下一拍；wait-fresh只等待新完整状态，每次最多休眠200µs，原截止不延长，不重推旧状态，不补发。**运动入口尚未修改**。诊断记录新/重复观测、虚拟间隔、接收/休眠/推理耗时以及异常触发瞬间的时间、阶段、缓存队列和半行状态；预期门控异常在串口关闭之前捕获时间，未知异常另行标明关闭后捕获。记录先入内存，结束后落盘，不覆盖旧报告。

它省略真实VEL写入、设备运动负载及运动专用位置/角度/制动门控，不能用于证明真实闭环时限；主机时间不是设备采样时间。两次运行不共享相同遥测，结果只用于定位线索，不是确定性因果实验。诊断最长0.5秒，未延长实际运动时间。

计时前有界等待本次QUERY/CALIB?/CONFIG?全部预期回执、有效观测、完整行尾和当前输入队列为空，避免把自己启动查询的尾流误算成活动期积压。这里仅检查回执齐全，不要求READY或运动配置匹配；保持DISABLED。2秒内未齐则报告启动未完成，不进入计时。
