# 当前设备的训练准备

设备事实的单一记录为 [`device-profile.json`](device-profile.json)。`measured` 来自操作者测量和固件输出，`configured` 是配置值而非电气测量，`motion_trial` 只描述一次试验。`unknown` 中的空值不能作为零或默认值进入模型。

## 可以使用的结论

- 挡块间距不是小车可移动距离。边界应从 `calibrated_travel_um / 2` 推导，再扣除 `soft_limit_margin_um`；训练终止边界还需预留控制与制动裕量。
- 摆角直立约为零，下垂位于 ±π 环绕点。设备的零点和方向参数由固件 NVS 保存。C 与 PC 策略程序启动只推送运行参数，不覆盖这些标定。
- 500 Hz 是静止状态流和查询应答的验收结果，不是 500 Hz 闭环或端到端延迟验收。现有策略周期保持 200 Hz；升级控制周期必须同步模型时间尺度、部署节拍、延迟和训练 rollout 时间跨度。
- STEP 持续频率仍待隔离波形测试。ISR 耗时的倒数不能证明引脚输出频率、脉宽或抖动合格，不能作为训练的实测速度上限。

## 训练前必须闭合的物理量

新杆的总长和质量不足以确定动力学。需要支点到质心的距离，以及绕质心的转动惯量。均匀细杆的 `m L² / 12` 只能作为明确标注的建模假设；安装夹具、支点偏移和质量分布会改变结果。小车移动质量也需核实。

当前 `Hexchip-Cartpole-Real-V2-v0` 的物理配置仍是参考模型，尚未换成这个设备档案。不要将该任务新训练的模型标记为已匹配当前设备；参数闭合后应同时更新质量、质心、惯量、轨道范围和执行器力限制，并重新训练。旧 checkpoint 不因修改配置自动变为新设备模型。

## 执行器时间尺度

动作延迟以策略步计：每次 `process_actions` 推进一次历史，之后各物理子步共享选出的目标。速度参考每次 `apply_actions` 使用 `physics_dt` 积分。例如 5 m/s²、物理步 2.5 ms、每策略步两个子步时，一个策略周期的最大参考速度增量是 0.025 m/s。

该动作支持逐物理子步调用的路径，当前核对对象为 Isaac Lab v3.0.0 PhysX。自行处理 decimation 的后端会被拒绝；Newton 需要独立适配和验证。CPU 单测不代替 Isaac Lab/GPU 训练启动和动力学核验。

训练观测当前是仿真瞬时速度。固件后向速度窗口的延迟与噪声尚未建模，不能用动作延迟代替。执行器 `tau` 和力限制也仍是待辨识假设，不是固件测得的响应参数。

## 部署程序的副作用

这些部署入口不是只读检查：C `run` 在 READY 后会主动回中再进入策略控制；C 无参控制台启动会推送运行参数；PC `--dry-run` 虽不发送 VEL，仍会推送运行参数。不要为了检查模型或串口而无意启动这些入口。此批仅禁止自动覆写设备标定，没有改变这些既有动作。

## 设备启动与协议边界

固件支持持久化标定时，重启仍需在 DISABLED 下将小车放到同一左参考位置，再用固件配套工具 `confirm-left` 确认。只有位置参考有效、摆角核验和供电就绪后，才由操作员决定使能。正常停止速度与关闭使能是不同动作；使用包含 DISABLE 支持的固件工具，不用 RESET 代替正常退出使能。

本仓库 C 控制台尚未接入新标定查询、confirm-left 和 DISABLE 流程，应由 `device-nerve-esp32` 配套工具完成这些步骤；旧 `calib` 含自动使能，不能作为新设备的默认启动流程。

实验分支的 `VEL_VALID` 是速度时间窗口有效性，不代表磁场健康。当前部署控制器尚未适配这一实验协议，不得直接用于该实验固件的运动闭环。需先补齐未知/无效/超时锁存、清缓存及不得自动恢复运动，并共同测试 PC 和 C 消费者。

## 离线检查

在含 PyTorch、pyserial 的 Python 环境中：

```bash
python -m unittest discover -s source/cartpole/tests -p 'test_*.py'
python deploy/v2/pc_runner_test.py
make -C deploy/v2/edge test
```

这些检查不连接串口、不加载模型、不启动训练。完整 Isaac Lab 环境、GPIO 波形、真实运动与闭环验收另行执行。
