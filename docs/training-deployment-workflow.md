# 训练、候选筛选与设备联调

## 功能入口

| 阶段 | 入口与行为 |
| --- | --- |
| 训练 | `scripts/rsl_rl/train.py` 使用 Isaac Lab 3.0 入口，显式将 actor、critic 映射到 policy 观测。完整结束回合计数与累计成功率独立记录。 |
| 保留候选 | `--training-candidates` 按完整回合窗口成功率排序，同分参考平均回合长度和奖励；周期保存仍保留。 |
| 冻结策略评估 | `scripts/evaluation/select_checkpoint.py --parallel-workers N` 有界并行评估候选，只对选中模型运行独立 holdout。必须指定与训练一致的任务。 |
| 导出与只读检查 | 官方导出后，使用 `deploy/v2/device/shadow.py` 检查观测与推理，不发送运动命令。 |
| 设备控制 | `deploy/v2/device/run_policy.py` 绑定模型、坐标与设备配置；支持限时运行及显式 `--continuous`。退出执行停车与禁用确认。 |

完整训练和筛选命令见 [训练候选与并行筛选](../scripts/evaluation/TRAINING_CANDIDATES.md)，设备命令和限制见 [设备联调](../deploy/v2/device/README.md)。

## 实验配置

原始 V2、Window16 和 Window16-Tau0 是不同任务。Window16 对速度观测应用 16 ms 窗口，Tau0 去除执行器的一阶滤波；它并不去除已有的命令延迟、加速度限制和力约束。对比时固定其他参数，不能根据文件名猜测模型配置。奖励目标为保持摆杆竖直、小车低速度及安全边界，不要求回到轨道中心。

训练触发保存的指标来自采样过程，保存的是更新后的参数。训练回合也可能跨多次策略更新，因此这些指标只是候选筛选依据，不能替代冻结策略评估。holdout 完成不等于达到真机验收要求。

## 设备边界

本策略运行器使用固件当前软限位，不在主机增加位置门或提前制动。固件参数仍需匹配读回；软限位不是预测制动，不能保证所有速度下的机械停止距离。现场必须能够独立停机。

主机保留角度、观测有效性、配置新鲜性、故障和时间门限。写入前若原观测过期，只能在原命令 6 ms 截止内废弃旧动作、取新帧重新推理；不得延长旧动作寿命或原截止时间。Windows、USB 和 Python 不构成硬实时控制系统。不应把同机并行训练时的资源争用与模型质量混为一谈。

## 验证状态

操作者已在 Windows / Isaac Lab 3.0 完成原始及 Window16-Tau0 训练、冻结策略评估、模型导出与设备短时闭环；指标记录和候选筛选已有现场反馈。这些结果来自对应历史版本，不是本整合提交的端到端验收。

本整合版本包含新加入的显式观测组、训练中候选保留、并行筛选、固件负责位置限制和候选过期重新推理。整合后仅作语法、入口及局部逻辑检查；完整训练、并行评估和最终设备控制仍需各自验证，不使用静态检查代替实测。不要切换或修改正在运行的训练工作区。
